# 来源格式与业务语义

## 解码原则（定义驱动，不按固定字段位置）

FIT 头 12 或 14 字节，`.FIT` 签名、数据长度及 CRC16 使用协议标准多项式。
`fitcodec.parse` 严格按文件内出现的**定义消息**逐条解码数据消息：

- 每条数据消息按其本地消息号**当前生效**的定义读取（架构端序、字段号、尺寸、基础类型）。
  同一本地消息号被新的定义消息重新定义后，旧布局立即失效，压缩时间戳参考值也随之重置。
- 架构字节决定多字节字段端序（0=小端，1=大端）；同一文件允许混合端序。
- 基础类型按 FIT SDK 表解码（enum/int/uint/float/string/byte 及 64 位类型），
  数组字段（尺寸为类型尺寸倍数）保留为列表；无效值按各类型固定无效标记识别，
  标记为 `invalid` 并保留原始字节，不参与数值统计。
- 标准字段的缩放与偏移只来自 `fitprofile` 中登记的配置，公式为
  `实际值 = 原始值 / 缩放 - 偏移`；未登记的标准字段保留字段号与原始字节，不命名、不猜测。
- 开发者字段**绝不套用标准 profile**（不会被猜成心率或位置）。其基础类型来自
  `field_description.fit_base_type_id`（SDK 枚举号，经 `FIT_BASE_TYPE_ID` 映射为内部
  基础类型键），名称、单位、缩放、偏移仅取自述消息；没有自述的开发者字段
  `description=None`，只保留原始字节。

## 压缩时间戳

压缩时间头（最高位置 1）不含时间字段，解码器以上一条**同本地消息号**的参考时间戳
为基准，用头部 5 位偏移恢复：`新戳 = 参考戳高位 + 偏移`，当参考戳低 5 位大于偏移时
说明 5 位计数器回绕，整体加 32 秒后再对 2^32 取模。恢复后的时间戳写回为合成的
字段 253（带 `synthesized` 标记），并更新该本地消息号的参考戳。缺少参考戳的压缩
消息按截断/结构错误处理，不会产生时间倒退。

## 消息关联（不按文件顺序等分）

`collector` 不依赖消息在文件中的排列位置：

- record 按时间戳落入 lap 的 `[start_time, timestamp]` 时间窗；
- lap 按同一时间窗规则落入 session；
- 落不进任何窗口的消息标记为 `orphan_record` / `orphan_lap` 事件。

## 完整性、事件与缺失区间

- 文件头无法识别抛 `ValueError`；截断、负载不完整、CRC 缺失或失败不抛异常，
  在 `errors` 中给出原因和字节偏移，并置 `complete=False`。
- 完整文件输出训练列表（`trainings`），每个训练带 session/lap 摘要、record 定位
  偏移列表与事件 ID；事件（session 起止、lap 标记、设备 event、无效测量、缺失区间）
  都带 `evidence`（消息字节偏移、本地/全局消息号、时间戳来源）。
- 相邻 record 时间戳不连续即生成 `missing_interval` 事件，给出闭区间缺口与两端
  消息偏移。截断/损坏文件只生成明确标注 `incomplete` 的 `preview`，**不进入完整
  训练列表**，其事件以 `complete=0` 单独存储。
- 训练与事件标识仅由文件 SHA-256 摘要与消息定位偏移推导，同一文件重复接收时
  标识稳定，数据库 UNIQUE 约束保证幂等。

## 本地夹具

`sampledata.samples()` 保留原有来源检查夹具；`sampledata_ext.device_files()` 新增
三份虚构设备文件，均为本地生成、可重复、不含真实个人数据：

- `device-activity.fit`：本地消息号重定义（record→大端 lap→event）、压缩时间戳
  回绕、开发者数组与无效测量、6 秒缺失区间、未知标准/开发者字段；
- `device-truncated.fit`：截断文件，用于不完整预览；
- `device-corrupt.fit`：结构完整但 CRC 损坏，用于完整性拒绝。

本地 HTTP 演练器采用方法与原始路径作为路由键，值为按调用次数返回的响应数组，耗尽后
维持最后一项。响应可定义 status、headers、text/base64、require_headers、chunk_bytes、
disconnect_after。每次请求保留方法、路径、头与正文摘要表示；演练器只监听回环地址。
原始输入上限 16 MiB 是接收入口的保护值；格式含义和截断错误不能被 HTTP 200 覆盖。
